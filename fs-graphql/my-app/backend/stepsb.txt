Step 2 — Create the backend dev.Dockerfile
Your backend's package.json tells us two important things:
"start": "node index.js",
"dev": "node --watch index.js"


- npm start runs the server normally.
- npm run dev runs the server with Node.js's built-in watch mode, which restarts it when watched files change.
For a development environment, we'll use npm run dev.

3. Understand the differences
Instruction	What it means
FROM node:24	Start with an image containing Node.js 24.
WORKDIR /usr/src/app	Choose the working directory inside the container.
COPY package*.json ./	Copy the dependency manifests.
RUN npm ci	Install the dependencies from the lockfile.
COPY . .	Copy the backend source files into the image.
CMD ["npm", "run", "dev"]	Start the GraphQL server in development mode.
The frontend and backend Dockerfiles look similar because both use Node.js and npm. The main difference is the command that starts each application.
- Frontend: npm run dev -- --host 0.0.0.0
- Backend: npm run dev
We'll handle network access and port configuration in Docker Compose.

Yes, exactly! You understood it correctly.
- If package-lock.json exists: use npm ci.
- If package-lock.json does not exist: use npm install.
Here is the difference:
Command	What it does
npm ci	Installs dependencies using the existing lockfile, keeping versions consistent. It fails if the lockfile is missing or out of sync with package.json.
npm install	Installs dependencies and can create or update package-lock.json when needed.
For your project:
- Backend: package-lock.json exists, so use npm ci.
- Frontend: package-lock.json exists, so use npm ci too.
One extra detail: npm ci removes the existing node_modules folder before installing dependencies. This is normally fine inside a fresh Docker image build.
You can remember it this way: ci = consistent installation from the lockfile; install = flexible installation that can update the lockfile.
